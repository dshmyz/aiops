# Capability Console 视觉重设计

## 目标

把 capability-console 的视觉从当前"半成品"状态重做一遍，建立统一的设计语言。产品定位是面向运维工程师的 AI 工具配置平台，视觉上要有技术感、信息密度高、长时间工作不累眼。

## 设计方向

深色科技风为主，浅色模式作为切换选项。

- 主色：青蓝 → 紫色渐变 (`#38bdf8` → `#6366f1`)
- 背景：近黑深蓝 (`#0a0e14`)
- 强调色：成功=绿、警告=橙、错误=红、信息=青蓝
- 字体：系统 UI 字体 + 等宽字体（能力名、路径、代码）
- 风格关键词：精密、克制、数据优先

### 字体

- UI 文字：系统字体栈 (-apple-system, "Segoe UI", "PingFang SC", ...)
- 代码/能力名/路径：等宽字体栈 ("SF Mono", Consolas, "JetBrains Mono", monospace)
- 字号层级：11px(辅助) / 12px(正文) / 13px(小标题) / 16px(标题) / 20px(大标题)

### 间距

4px 基准网格：4 / 8 / 12 / 16 / 24 / 32

### 圆角

- 小圆：6px（标签、徽章）
- 中圆：8px（按钮、输入框）
- 大圆：12px（卡片、面板）
- 超大圆：16px（大卡片、弹窗）

### 阴影

极克制使用。深色模式下阴影几乎不可见，主要靠边框区分层级。唯一有阴影的是主按钮（发光感）。

## 布局结构

整体保持 4 步工作流的产品结构，视觉上重新组织：

```
┌─────────────────────────────────────────────────────┐
│  ⚙  │  AI Capability Studio              [🌙] [+ 新建] │  ← Topbar
├────┼────────────────────────────────────────────────┤
│    │  [✓ 接入] ── [✓ 选择] ── [③ 评审] ── [4 AI试问]  │  ← Stepper
│    ├──────────────────┬──────────────────────────────┤
│    │  能力清单        │  评审发布                     │
│    │  ┌─ KPI 色块 ─┐  │  ┌─ 发布检查 ─────────────┐ │
```

具体页面的布局：

### 助手页（assistant view）
- 居中三栏布局：快捷方式 | 对话区 | 调用详情
- 视觉上比管理页更"轻"，减少信息密度

### 接入页（step 1: source）
- 主区域居中放置 Swagger 输入表单
- 右侧显示当前能力状态统计

### 选择页（step 2: candidates）
- 顶部：Swagger 源信息 + 重新预览
- 中部：筛选 + 候选列表（卡片式或表格式）
- 底部：选中统计 + 生成草稿按钮（sticky）

### 评审页（step 3: review）
- 左侧：能力列表 + KPI + 筛选 + 搜索
- 右侧：发布检查 + 详情编辑 + 测试 + AI 预检
- 每个编辑区块用独立卡片包裹

### AI 试问页（step 4: ai）
- 左侧：已发布能力列表
- 右侧：AI 试运行（大输入框 + 结果区）

## 组件规范

### 按钮
- 主按钮：渐变背景 + 发光阴影
- 次按钮：边框 + 透明背景
- 幽灵按钮：无边框，hover 出背景
- 尺寸：默认高 32px，小号 28px

### 输入框
- 深色背景 + 边框
- focus 时边框变主色
- 等宽字体用于路径、JSON、能力名

### 卡片
- 深色背景 + 1px 边框 + 12px 圆角
- 卡片头：标题 + 右侧辅助信息
- 卡片体：内边距 16px

### KPI 卡片
- 2x2 网格
- 标题 10px uppercase
- 数字 18px 等宽字体 + 语义色

### 徽章 / 标签
- 圆角 999px
- 语义色背景（半透明）+ 同色文字

### 步骤指示器
- 横向居中
- 已完成：绿色 + ✓
- 当前：渐变填充 + 高亮
- 未到达：灰色
- 步骤之间用细线连接

## 深浅主题切换

- CSS 变量驱动
- 切换按钮在顶栏右上角
- 默认深色（因为产品定位是运维工具）
- 浅色模式的配色：白底灰字蓝主色，参考 Linear/Vercel 风格

## 不变的东西

- 功能逻辑完全不变
- `data-test` 属性完全不变（保证测试不挂）
- Vue 组件结构大体不变（只改 class/style 和少量 DOM 结构）
- 4 步工作流的产品逻辑不变

## 测试策略

- 现有 45 个测试必须全通过（因为 `data-test` 不改动）
- 不新增视觉回归测试
- 手动验证：每个步骤页面在深浅主题下都能正常显示

## 实现计划

1. 建立 CSS 变量系统（深色 + 浅色两套）
2. 重写布局框架（sidebar + topbar + stepper）
3. 逐个页面重做样式
4. 深浅主题切换功能
5. 验证测试通过 + 手动检查

预计改动文件：
- `src/styles.css` — 全部重写
- `src/App.vue` — 模板结构微调（添加 wrapper、改 class、少量 DOM 重组）
- 不新增组件文件：第一版先集中在 styles.css + App.vue 里改，等视觉设计稳定后再考虑拆分子组件。理由：视觉重设计阶段改 class 名和 DOM 结构很频繁，拆组件会增加改动成本；等设计定稿了再拆更合理。
